# BookSpace

BookSpace — веб-приложение на Django для публикации материалов о литературных произведениях. Пользователи могут создавать публикации, указывать категории и авторов произведений, оставлять комментарии и вести профиль.

## Возможности

- Регистрация и вход на основе встроенной системы аутентификации Django.
- Личный профиль пользователя с аватаром и информацией о себе.
- Публичные профили пользователей.
- Создание, просмотр, редактирование и удаление публикаций.
- Привязка публикаций к категориям и одному или нескольким авторам произведений.
- Страницы списка и подробной информации об авторах и категориях.
- Комментарии к публикациям для авторизованных пользователей.
- Поиск публикаций по названию.
- Пагинация списков.
- Проверка владельца публикации или записи автора при редактировании и удалении.

## Запуск локально

Требуется установленный Python. Команды ниже приведены для Windows PowerShell; в других оболочках активация виртуального окружения может отличаться.

1. Клонировать репозиторий и перейти в папку проекта:

   ```bash
   git clone https://github.com/dmitryi-88/blog.git
   cd blog
   ```

2. Создать и активировать виртуальное окружение:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

3. Установить зависимости:

   ```bash
   pip install Django python-dotenv Pillow
   ```

   После установки зафиксировать фактические версии окружения:

   ```bash
   pip freeze > requirements.txt
   ```

4. Создать файл `.env` в корне проекта. В нём должна быть переменная `SECRET_KEY`:

   ```dotenv
   SECRET_KEY=вставьте-сгенерированный-секретный-ключ
   ```

   Сгенерировать ключ можно командой:

   ```bash
   python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
   ```

5. Применить миграции:

   ```bash
   python manage.py migrate
   ```

6. При необходимости создать администратора:

   ```bash
   python manage.py createsuperuser
   ```

7. Запустить сервер разработки:

   ```bash
   python manage.py runserver
   ```

   Приложение будет доступно по адресу `http://127.0.0.1:8000/`. Корневой адрес перенаправляет на `/blog/`.

## SCSS

Основные стили находятся в `static/scss/`. Главный файл — `static/scss/main.scss`; он подключает остальные модули. Скомпилированный файл подключается в `templates/base.html`.

Если Sass CLI установлен, для автоматической компиляции можно выполнить:

```bash
sass --watch static/scss/main.scss:static/css/main.css
```

## Основные разделы

| URL | Назначение |
| --- | --- |
| `/` | Перенаправление на ленту публикаций |
| `/blog/` | Лента опубликованных публикаций |
| `/blog/<id>/` | Страница публикации и комментарии |
| `/blog/create/` | Создание публикации |
| `/blog/authors/` | Список авторов произведений |
| `/blog/authors/<id>/` | Страница автора произведения |
| `/blog/categories/` | Список категорий |
| `/blog/categories/<id>/` | Страница категории |
| `/blog/search/` | Поиск публикаций по названию |
| `/account/register/` | Регистрация |
| `/account/profile/` | Личный профиль |
| `/account/profile/edit/` | Редактирование личного профиля |
| `/account/users/<username>/` | Публичный профиль пользователя |
| `/admin/` | Панель администратора Django |

Маршруты входа, выхода и восстановления пароля подключены через `django.contrib.auth.urls` под префиксом `/account/`.

## Модель данных

- `User` — стандартная модель пользователя Django.
- `UserProfile` — дополнительный профиль пользователя, связанный с `User` отношением OneToOne.
- `Category` — категория публикации.
- `Author` — автор литературного произведения. Один автор может быть связан с несколькими публикациями.
- `Post` — публикация пользователя; связана с одной категорией, одним или несколькими авторами произведений и пользователем-создателем.
- `Comment` — комментарий к публикации, созданный авторизованным пользователем.

В проекте важно различать `Author` и `Post.writer`: первый обозначает автора произведения, второй — пользователя сайта, который разместил публикацию.

## Доступ и безопасность

Создание публикаций, авторов произведений и комментариев требует входа в систему. Редактирование и удаление публикации или записи автора ограничено владельцем записи. Проверка выполняется не только в шаблоне: соответствующие UpdateView и DeleteView фильтруют queryset по `request.user`.

Для реального развёртывания необходимо отдельно настроить production-режим: отключить `DEBUG`, задать `ALLOWED_HOSTS`, использовать надёжный `SECRET_KEY` из окружения, настроить HTTPS, почтовый backend и раздачу static/media-файлов. Текущие настройки предназначены для локальной разработки.
